# SLI, SLO, SLA, and Error Budgets

- **SRE-021 — User-Centric SLI:** Critical services MUST define indicators that reflect user-visible reliability where measurable.
- **SRE-022 — Availability Definition:** Availability MUST have an explicit numerator, denominator, exclusions, and measurement source.
- **SRE-023 — Latency SLI:** Latency objectives SHOULD use meaningful percentiles rather than averages alone.
- **SRE-024 — Correctness SLI:** Where wrong responses are materially harmful, correctness MUST be measured separately from transport success.
- **SRE-025 — Freshness SLI:** Data or content services with freshness expectations MUST define freshness indicators.
- **SRE-026 — Durability SLI:** Systems responsible for persistent data MUST define appropriate durability expectations.
- **SRE-027 — SLO Ownership:** Each production SLO MUST have an owner responsible for interpretation and action.
- **SRE-028 — SLO Period:** Every SLO MUST define its evaluation window and calculation method.
- **SRE-029 — SLO Realism:** SLOs MUST reflect business need and architecture capability rather than arbitrary perfection.
- **SRE-030 — No Hidden Exclusions:** Exclusions from SLO calculations MUST be explicit and justified.
- **SRE-031 — Dependency-Aware Objectives:** Service objectives MUST account for critical dependency limits when setting realistic targets.
- **SRE-032 — SLA Separation:** External or contractual SLA commitments MUST be distinguished from internal engineering SLOs.
- **SRE-033 — SLA Evidence:** Contractual availability claims MUST be supported by reproducible measurement evidence.
- **SRE-034 — Error Budget Calculation:** Services using SLOs SHOULD calculate remaining error budget for the active period.
- **SRE-035 — Error Budget Policy:** Critical services SHOULD define actions when error budget consumption exceeds agreed thresholds.
- **SRE-036 — Burn Rate Alerts:** Multi-window or equivalent burn-rate alerting SHOULD be used for important SLOs.
- **SRE-037 — Release Risk and Budget:** Sustained SLO breach SHOULD influence release velocity and reliability work prioritization.
- **SRE-038 — SLO Change Control:** Material SLO definition changes MUST be documented and approved by relevant owners.
- **SRE-039 — Dashboard Visibility:** SLO status and error-budget consumption SHOULD be visible to engineering and service owners.
- **SRE-040 — Periodic SLO Review:** SLO usefulness, thresholds, exclusions, and business alignment MUST be periodically reassessed.
